# OUTPOST: MARS

## What This Is

OUTPOST: MARS is a browser-based, turn-based 2D Mars outpost survival and astronaut mission trainer designed for children aged 7–12. Players take on the role of Outpost Commander during an intense **Seven-Sol campaign**, managing **Sun Power**, **Life Support**, and **Storm Shield** on the Martian surface while responding to space-weather events and astronaut health challenges grounded in authentic NASA resources (DONKI, RadLab, OSDR, Mars Trek).

## Core Value

Translate real NASA and space agency data into an intuitive, empowering, and scientifically grounded 2D mission trainer where young learners discover how authentic science and engineering keep humans alive on Mars.

## Target Audience & Pedagogy

- **Primary Audience:** Children aged 7–12 (Upper Elementary / Middle School STEM).
- **Tone:** Encouraging, scientifically authentic, and adventurous without being punishing or overly complex.
- **Pedagogical Loop:** Learn a real space concept → Make an engineering decision → Observe consequences → Receive positive reinforcement & transparent scientific debrief.

## Gameplay Model

### 3 Core Managed Resources
1. **Sun Power:** Kilowatts (kW) generated by solar panels and stored in battery cells to run systems through the Martian night and extreme subzero cold.
2. **Life Support:** Combined consumable reserve sustaining the crew (with Oxygen, Water, and Nutritional sub-values visible as educational breakdowns).
3. **Storm Shield:** Structural and radiation shielding readiness (regolith berms, shelter integrity) protecting the crew from space radiation.

### Crew Safety (Outcome Indicator)
- **Crew Safety** is an **outcome indicator** (Nominal / Caution / Danger), NOT a spendable resource. It reflects the overall health, radiation exposure, and life-support stability of the 4 astronauts.

### 4 Essential MVP Modules
1. **Habitat:** Living quarters, communications hub, and crew exercise/health station (counteracting physical deconditioning).
2. **Solar Array & Battery:** Consolidated photovoltaic generation and overnight energy storage unit (supplying Sun Power).
3. **Life Support System:** Consolidated atmospheric oxygen extraction, water recycling, and filtration unit.
4. **Storm Shield / Shelter:** Compacted Martian regolith and radiation barrier.
*(Optional Upgrade / Scenario Event: CSA Hydroponics Greenhouse).*

## API Key, Security & Offline Architecture

- **NASA API Key Protocol:** The user will personally generate a free NASA API key from `https://api.nasa.gov/`. Do **not** request it now; request it only when the exact integration step requires it.
- **Pre-Integration Verification:** Before using any resource, verify current endpoint, authentication requirements, rate limits, response schema/format, and usage/licensing constraints. Do not assume every resource requires a NASA API key.
- **Critical Security Rules:**
  - Never hardcode secrets.
  - Never put a secret in a frontend `VITE_*` variable.
  - Never expose credentials in browser JavaScript.
  - Never commit `.env` or secrets.
  - Prefer private local ingestion scripts that generate validated, version-controlled snapshots.
  - The deployed game must remain 100% playable offline with bundled snapshots.

## Scientific Integrity

Every scientific data record and game mechanic adheres to strict three-tier taxonomy:
- **`[REAL]`**: Direct empirical measurements from verified instruments or published space science literature (e.g. MSL Curiosity RAD Gale Crater baseline of $0.64 \pm 0.12\text{ mSv/day}$; Perseverance MEDA pressure ranges of $700\text{--}800\text{ Pa}$; NASA BVAD life-support consumption).
- **`[DERIVED]`**: Values calculated using verified physical or orbital equations (e.g. CME transit time to Mars from shock speed).
- **`[GAME-SIMPLIFIED]`**: Pedagogical abstractions and game-balance parameters designed for children aged 7–12 (e.g. the $+50\text{ mSv}$ storm surge is an intentionally exaggerated worst-case drill, 1,000x larger than the $\approx 50\ \mu\text{Sv}$ event observed on Mars in 2013; $80\%$ regolith attenuation is a simplified balance rule).

Every data record must preserve source URL, dataset identifier, retrieval date, units, measurement context, methodology, and limitations where available. Never invent measurements or citations. Never equate DONKI event information with Mars surface dose. Never equate ISS RadLab measurements with Mars surface measurements.
